# クラウドセッションにおける規則

Claude Code のクラウドセッションで読み込む規則。

- GitHub への書き込み（`git push`、PR、Issue など）が必要なとき、リポジトリが非公開なとき、非公開かどうか分からないときは、クローンする前に `add_repo` でセッションに追加する。書き込みが必要なら `access: "push"` を付ける。
  - 事前にリポジトリの存在を確かめない（curl、`git ls-remote` などは使わない）。非公開リポジトリは、認証なしだと実在しても 404 になる。
  - `add_repo` は権限を付けるだけで、クローンはしない。公開リポジトリの読み取りだけなら「何も追加しない」と返るだけなので、迷ったら呼んでよい。
  - 作業の途中で書き込みが必要になったら、その時点で `add_repo` を実行する。
- `add_repo` の返答に書かれたクローン先に、返答に書かれたコマンドでクローンする。追加したリポジトリは `/home/user/<repo>`、追加していない公開リポジトリは `/home/user/<owner>/<repo>` になる。
  - クローン先に既にディレクトリがある場合は、`git -C <path> remote get-url origin` で対象のリポジトリか確かめる。同じリポジトリならそのまま使う。別のリポジトリなら消さずに、`/home/user/<owner>/<repo>` にクローンしてその旨を報告する。この場合は `register_repo_root` を使えない。
  - リポジトリの中に別のリポジトリを置かない。
  - 返答のコマンドは `--depth 1` でクローンするので、プッシュする前に `git -C <path> fetch origin <default-branch>` を実行する。実行しないと全ツリーを再送して 413 で拒否される。
  - 429 が返ったら、Retry-After の秒数だけ待って 1 回だけ再試行する。
- `add_repo` で追加したリポジトリは、クローンしたあとに `register_repo_root` に owner と repo を渡す（`directory` は渡さない）。そのリポジトリの `CLAUDE.md`（と、そこから `@` で参照するファイル）、skills、plugins が読み込まれ、作業ディレクトリにも追加される。
- `register_repo_root` を使っていないリポジトリは、クローンした `CLAUDE.md` を読んでから作業する。
- Git の操作は `git -C <path>` で対象のリポジトリを明示する。
- コミットするときは、ファイルを個別に指定して `git add` する。`git add -A` と `git add .` は使わない。
- 作業を始める前と報告するときに、どのリポジトリで何をしたかを明記する。
