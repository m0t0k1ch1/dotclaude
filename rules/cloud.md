# クラウドセッションにおける規則

Claude Code のクラウドセッションで読み込む規則。

- リポジトリは `/home/user/<owner>/<repo>` にクローンして使う。
  - `add_repo` の返答に書かれたクローン先とクローンコマンドは使わない。
  - 既にディレクトリがある場合は、`git -C <path> remote get-url origin` で対象のリポジトリか確かめてから使う。消して作り直さない。
  - リポジトリの中に別のリポジトリを置かない。
- GitHub への書き込み（`git push`、PR、Issue など）が必要なとき、リポジトリが非公開なとき、非公開かどうか分からないときは、クローンする前に `add_repo` でセッションに追加する。書き込みが必要なら `access: "push"` を付ける。
  - 事前にリポジトリの存在を確かめない（curl、`git ls-remote` などは使わない）。非公開リポジトリは、認証なしだと実在しても 404 になる。
  - `add_repo` は権限を付けるだけで、クローンはしない。公開リポジトリの読み取りだけなら「何も追加しない」と返るだけなので、迷ったら呼んでよい。
  - 作業の途中で書き込みが必要になったら、その時点で `add_repo` を実行する。権限はリポジトリ単位で付き、クローン先のパスには依存しない。
- `git clone` でクローンする。
  - `add_repo` で追加していない公開リポジトリは、`GIT_LFS_SKIP_SMUDGE=1` を付けてクローンする。匿名の読み取り経路は Git LFS のオブジェクトを配信しないため、付けないと LFS を使うリポジトリでクローンが失敗する。
  - `--depth` を付けてクローンした場合は、プッシュする前に `git -C <path> fetch origin <default-branch>` を実行する。実行しないと全ツリーを再送して 413 で拒否される。
  - 429 が返ったら、Retry-After の秒数だけ待って 1 回だけ再試行する。
- `add_repo` で追加したリポジトリは、クローンしたあとに `register_repo_root` に owner、repo、クローン先のパスを渡す。次のターンから、そのリポジトリの `CLAUDE.md`、skills、plugins が読み込まれる。
- クローンしたリポジトリの `CLAUDE.md` を読んでから作業する。
- git の操作は `git -C <path>` で対象のリポジトリを明示する。
- コミットするときは、ファイルを個別に指定して `git add` する。`git add -A` と `git add .` は使わない。
- 作業を始める前と報告するときに、どのリポジトリで何をしたかを明記する。
